# MES 设备建模设计概览

> 本文是完整设计文档 [`2026-07-20-mes-equipment-modeling-design.md`](./2026-07-20-mes-equipment-modeling-design.md) 的**简要概览**，用于快速理解全貌。细节、取舍推导、对照表请读完整文档。

---

## 一句话定位

建立**可管理、可调度、可控制、可扩展**的设备模型：用**位置漏斗 + 粗粒度能力匹配**完成设备分配，用**程序层封装**完成设备控制，工艺与设备解耦。

## 五个核心决策

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 工艺与设备解耦 | 粗粒度能力匹配（布尔资格，不做参数精筛）|
| 2 | 位置模型 | 4 级漏斗：工艺→产线→房间→设备；工位=物理位置，不参与匹配 |
| 3 | 能力来源 | 类型默认 + 实例可增删（与配置/程序绑定同构）|
| 4 | 状态分层 | 三层正交：连接态 × 运行态 × 健康态 + 占用标志；业务状态归工序 |
| 5 | 控制抽象 | 设备程序层（Batch 抽象）：工艺调程序，程序执行器按 executeMode 路由 |

## 设备分配逻辑

```
选定产线 ∩ 工序允许的房间 ∩ 房间内具备所需能力的设备 ∩ 状态可分配 → 选一台
```

## 设备控制逻辑

```
工艺 ──ExecuteProgram(prog, params)──► 程序执行器
                                          │
                            按 executeMode 路由
                          ┌───────────────┴───────────────┐
                          ▼                               ▼
                  DIRECT（裸点位）                 BATCH（自带控制层）
                  展开成点位操作序列                 下发配方 + 收事件
                          │                               │
                          └───────────────┬───────────────┘
                                          ▼
                              统一程序事件流
                          Started / Progress / Completed / Aborted
```

## 设备模型骨架

```
Equipment（设备实例）
 ├─ 身份      code, name, model, vendor, SN
 ├─ 归属      stationId（上溯 room / line）
 ├─ 分类      categoryId（统计展示用）
 ├─ 类型      typeId → 继承默认能力、规格模板、控制模板（程序绑定的默认模板也由类型带出，实例可覆盖，见下）
 ├─ 能力      effectiveCapabilities = 类型默认 ∪ 新增 − 移除      [匹配键]
 ├─ 规格参数  量程/精度/转速…（仅展示，不参与匹配）
 ├─ 三层状态  连接态 × 运行态 × 健康态 + 占用标志 → 派生 allocatable
 ├─ 控制配置  ControlProfile（协议/endpoint/映射，类型默认+实例覆盖）
 ├─ 采集配置  AcquisitionProfile（采集点/周期/报警，与控制正交）
 ├─ 执行模式  executeMode: DIRECT | BATCH
 └─ 程序绑定  programBindings[]（程序→实现，类型默认+实例覆盖）

EquipmentType（设备类型）
 ├─ 分类、默认能力、规格模板
 ├─ 控制配置模板 controlTemplate（协议 + 默认点位映射）
 └─ 默认程序绑定 programBindings[]

Program Library（程序库，平台共享）
 └─ Heating / Cooling / CIP / SIP …（设备无关的逻辑定义）

ProcessStep（工序）
 ├─ 绑定多个房间 allowedRooms[]
 ├─ 所需能力 requiredCapabilities[]                              [匹配键]
 └─ 程序调用 ExecuteProgram(name, params)                        [执行入口]
```

## 分类 vs 类型 vs 能力（三者最易混）

中文里都像"设备的类别"，但职责完全不同。本表只辨析这三个**易混概念**；程序绑定属于执行层（见"设备模型骨架"和"配置组织原则"），不在此列。

| 维度 | 职责 | 参与匹配？ | 形态 | 例子 |
|---|---|---|---|---|
| **分类 Category** | 统计、分组、展示 | ❌ 不参与 | 树形 | 加工设备 / 检测设备 / 容器 |
| **类型 Type** | 继承默认能力 + 规格模板 + 控制模板 | ✅ 间接（带出默认能力）| 扁平或浅层 | 离心机 / 电子秤 / 反应釜 |
| **能力 Capability** | 匹配的硬筛条件 | ✅ 直接 | 扁平标签集 | 可离心 / 可称量 / 可升温 |

> 一句话：**分类**是图书馆分区（找书用），**类型**是书的版次（决定内容与默认属性），**能力**是书讲什么主题（决定能不能回答你的问题）。工艺匹配只看**能力**；类型通过"默认能力"间接影响匹配；分类纯属展示统计。
>
> **程序绑定**：独立于上述三者，属于"执行层"——程序库（Heating/CIP…）平台共享，**程序绑定**（这台设备如何执行某程序）走"类型默认 + 实例覆盖"，与能力、控制配置同构（见"配置组织原则"表）。

## 三层状态机（正交，非单一字段）

| 层 | 取值 | 来源 |
|---|---|---|
| 连接态 Connection | Offline / Connecting / Online | 协议驱动 |
| 运行态 Operation | Idle / Running / Pause / Stopping / Error | 设备点位上报 |
| 健康态 Health | Normal / Alarm / Repair / Maintenance / Disabled | 维保流程+报警 |
| 占用标志 | bool + occupant + 心跳 | 工序执行引擎 |

**派生** `allocatable = Online ∧ Operation∈{Idle,Running,Pause} ∧ Health=Normal ∧ 未占用`

**状态获取与可信度**（详见完整文档 §7.8）：三层状态由不同机制获取（连接态靠探活副产品、运行态靠订阅/轮询、健康态靠业务登记），**不需要 MES 持续硬连设备**。Offline 时运行态陈旧、健康态仍可信；安全性靠 allocatable 第一关（Online）兜底，断连设备直接出局，重连后刷新运行态。

## 位置漏斗

```
工艺（绑多产线）→ 排程选定产线 → 工序（绑多房间）按产线选房间
                                         │
                                         ▼
                            房间 → [工位透明] → 设备
                            （工位=物理坐标，不参与匹配）
```

## 赋码体系

赋码要支撑两类反查：**按位置反查**（这条产线/这个房间有哪些设备）、**按能力反查**（哪些设备具备某能力）。

| 对象 | 编码示例 | 用途 |
|---|---|---|
| 产线 | `LINE-01` | 位置反查 |
| 房间 | `LINE-01-RM-003` | 位置反查（含上溯）|
| 工位 | `LINE-01-RM-003-ST-02` | 物理坐标（含上溯）|
| 设备 | `EQP-2026-0001` | 全局唯一 |
| 类型 | `TYPE-CENTRIFUGE` | 能力继承锚点 |
| 能力 | `CAP-CENTRIFUGE` | 匹配键 |

**三条原则**：
- **位置码含上溯**：工位码内嵌产线/房间段，便于一眼定位，也便于按前缀反查（`LIKE 'LINE-01-RM-003-%'` 查该房间所有设备）。
- **设备码独立**：设备可能挪位置，故设备码**不内嵌位置**——挪位置不改码。
- **能力码/类型码全局稳定**：一经发布不改名（改用版本/废弃机制），因为它们是匹配和继承的键。

**反查模式**：

```
按位置： WHERE stationId LIKE 'LINE-01-RM-003-%'          → 该房间所有设备
按能力： WHERE 'CAP-CENTRIFUGE' = ANY(effectiveCapabilities) → 具备该能力的设备
分配候选： WHERE stationId LIKE 'LINE-01-RM-003-%'
          AND 'CAP-CENTRIFUGE' = ANY(effectiveCapabilities)
          AND allocatable = true
```

## 配置组织原则（三处同构）

| 模型 | 类型默认 | 实例覆盖 |
|---|---|---|
| 能力 | defaultCapabilities | 新增 / 移除 |
| 控制配置 | controlTemplate（协议+映射模板）| endpoint / 映射增删 |
| 程序绑定 | 类型默认 programBindings | 实例配方/点位序列 |

**协议不可在实例覆盖**——换协议应新建类型，守住类型契约。

## 监控/断电恢复/GMP 责任归属

| 责任 | DIRECT 路径 | BATCH 路径 |
|---|---|---|
| 持续监控 | MES 程序执行器 | 现场控制层 |
| 断电恢复 | MES 持久化程序实例状态 | 现场控制层保持 |
| GMP 审计 | 程序执行器落程序级审计 | 现场记录 + MES 归档 |

## 数据采集存储（时序，独立于业务数据）

采集数据（温度曲线/振动/电流）是**时序数据**，与业务数据存储需求相反（高吞吐写入、按时间范围查、降采样聚合、append-only），**不能塞进关系库**。按用途分三层：

| 层 | 用途 | 保留期 | 选型取向 |
|---|---|---|---|
| 热数据 | 实时缓冲（监控/报警/运行态判定）| 秒~分钟，滚动覆盖 | 内存/缓存，不落库 |
| 温数据 | 近期原始值（回放/分析/批记录数据回放）| 天~月 | **时序库** |
| 冷数据 | 远期归档（趋势/合规存档）| 年~永久（GMP 常 5–10 年）| 降采样表/对象存储 |

**关键设计**：

- **数据模型**：`timestamp + tags(equipmentId/pointId/batchId/stepInstanceId) + fields(value) + quality`。tags 决定可查询模式。
- **业务上下文 tag**：写入时带 `batchId/stepInstanceId`（从占用标志取），让批记录能直接拉出"本批次相关采集曲线"——GMP 追溯必需。
- **采集与状态联动**：采集值 → 报警规则 → 触发健康态 `Alarm`（§7），同时写报警事件供追溯。
- **AcquisitionProfile 扩展**：采集点带量纲/周期/质量规则/存储分层/降采样策略/报警阈值（§14.4）。
- **选型暂不绑定**，待现场调研后定（§15 开放问题）。

## 核心设计哲学

- **用位置漏斗替代能力匹配承担灵活性**——可预测、可实现，适合制药 MES。
- **类型默认 + 实例覆盖**贯穿能力、配置、程序绑定——同构降低认知成本。
- **工艺只声明意图**（要什么能力、调什么程序），**不碰实现**（点位、配方、协议）。
- **分层收敛工程责任**——监控/断电恢复/审计由专门层兜底，不散落业务。
