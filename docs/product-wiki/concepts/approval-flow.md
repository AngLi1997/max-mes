# 审批流统一架构

> 本页讲审批流引擎的统一架构、编码规范与节点能力。具体业务审批的状态机详见 [[version-publish-mechanism]]。

## 平台 SDK + 各系统独立配置

为保证使用效率，平台提供**统一的审批流 SDK**，由各业务系统（platform / mes / lims）独立引入并配置。各系统的流程模板相互隔离，但引擎与节点能力一致。

## 编码规范（6 位 = 3+3）

```
120 020 001
└─分类编码─┘ └类型编号┘
   (3位)        (3位)
```

- **分类编码（3 位）**：标识模块分类，等于对应一级菜单的编码（如 `120`=MES, `020`=生产配置）。
- **类型编号（3 位）**：标识该分类下的流程类型，递增序列。
- **默认流程**：每个底级分类内置一个 id 与编码相同的默认流程，初始版本只含一个审核节点且未启用。

## MES 内置流程类型（系统 120）

| 分类编码 | 分类名称 | 类型编号 | 类型名称 |
|---|---|---|---|
| 120020 | 生产配置 | 120020001 | 记录审批 |
| 120020 | 生产配置 | 120020002 | 工艺审批 |
| 120030 | 生产管理 | 120030001 | 生产计划审批 |
| 120040 | 批签发 | 120040001 | 批签发审核 |

> 工艺/操作规程的"启用审批"复用工艺审批流程类型；操作规程"停用审批"亦复用此类型，但状态流转不同（见下文）。

## 流程模型状态机

```
新建 ──保存──► 设计中(编辑中) ──发布──► 启用中 ──升级──► 设计中（新版本）
                  │                    │
                  └──升级──► 设计中    └──被新版本替换──► 历史
```

- **同流程编号下**：启用中状态流程模型**有且仅有一个**；编辑中状态可多个。
- **升级版本**：启用中/历史状态均可升级，进入新版本的编辑中状态，保留源版本号记录。
- **发布冲突**：发布时若同流程模块存在启用中版本且存在进行中流程实例，发布失败。
- **多用户并发**：A 发布成功后，B 再点击保存/发布会提示"该流程模型已完成发布，不允许再次进行保存/发布"。

## 任务节点能力

每个任务节点配置分三段：**基本信息 / 审核配置 / 通知配置**。

### 基本信息
- 节点名称（必填，默认"任务节点"）
- 描述（≤50 字符）
- **密码认证**：默认否；勾选"是"后，审核人在该节点执行审核通过/不通过/转交/回退前需输入当前登录用户密码进行身份认证。

### 审核配置
- **处理人配置**：必填，二选一或同时配置
  - 分配审核人员（来自平台用户管理）
  - 分配审核角色（来自平台角色管理；角色下任一人员完成审核即视为该角色完成）
- **节点功能**（默认勾选审核通过/不通过且不可取消）：
  - 审核通过、审核不通过、回退（回退至上一节点，开始/并行网关不可回退）、抄送（节点完成后推送消息给抄送人）
  - 当前阶段**不做**转交
- **审批规则**（必填，默认或签）：
  - 或签：任一审核人完成即节点完成
  - 会签：可选「所有待审人」「所有待审角色」或同时；待审人中任一"不通过"→节点不通过；任一"退回"→回退至上一节点
- **审批意见** / **备注**：可配置"必须"或"非必须"，默认非必须

### 通知配置
- 节点完成消息通知：节点完成时自动推送消息给配置的接收人（与流程待办消息通知不冲突）

### 必填项校验交互
- 多页配置存在未填项时，点"确定"跳转至**首个未填页面**。
- 若当前页本身就有未填项，则停留当前页。
- 校验优先级：画布完整性 > 唯一性 > 功能校验。

## 各业务审批的统一与差异

引擎统一，但**实例业务名称**和**实例编号**因业务而异：

| 流程类型 | 实例业务名称 | 实例业务编号 |
|---|---|---|
| 记录审批 | 记录名称（如「人血白蛋白批记录」） | 版本号 |
| 生产 BOM 审批 | 生产 BOM 名称 | 版本号 |
| 工艺审批 | 工艺名称 | 版本号 |
| 操作规程审批 | 文件名称 | 版本号 |
| 指令单审批 | 产品名称（如「冷沉淀」「FV 沉淀」） | 生产批号 |
| 批记录审批 | 产品名称 | 生产批号 |
| 批签发审核 | 成品名称 | 生产批号 |

> 规律：配置端对象（记录/工艺/BOM/操作规程）用版本号，执行端对象（指令单/批记录/批签发）用生产批号。详见 [[version-publish-mechanism]]。

## 启用审批 vs 停用审批（操作规程特例）

操作规程在「确认」或「失效」状态可发起**启用审批**，在「待生效」或「生效」状态可发起**停用**（停用无审批，确认后直接转失效）。审核不通过时：
- 启用审批不通过：版本回到「确认」
- 停用审批不通过：版本回到原状态（待生效或生效）

## 审批流追溯

[[audit-trail-and-logs]] 的"审批流追溯"提供跨业务系统统一查询入口：
- 树结构：服务 tab（MES / LIMS / 生产App）→ 流程类型 → 流程名称
- 列表字段：实例业务名称、实例业务编号、发起人、发起/结束时间、结束状态、处理人
- 详情页：流程节点列表，按节点层级顺序排列（同层级按处理时间顺序）
- 处理人记录规则：或签/会签 × 人员/角色，按节点维度逐人记录

## 实例运行期管理

流程实例在「进行中」状态可执行：
- **挂起**：填写挂起原因，实例转为「挂起」，按钮变「启用」
- **启用**：填写启用原因，实例恢复「进行中」
- **终止**：填写终止原因，实例转为「终止」，仅可查看详情
- **详情**：展示流程图（节点状态用边框颜色标识）+ 节点处理记录
