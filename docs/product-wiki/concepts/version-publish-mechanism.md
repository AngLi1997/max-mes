# 版本发布机制

> 本页是配置端版本生命周期的**统一范式**。所有需要"草稿→审批→生效"的对象都遵循此模式。
> 与 [[product-overview]] 的两端模型强绑定：配置端定义版本，使用端引用生效版本。

## 适用范围

共 9 类对象遵循本机制（差异见下文「分类变体」）：

| 对象 | 是否需审批 | 是否支持生效日期 | 是否有作废 |
|---|---|---|---|
| 工艺 | 是 | 是 | 否（用"失效"） |
| 操作规程 | 是 | 是 | 否 |
| 配方 | 是 | 否（启用即生效） | 否 |
| 生产 BOM | 是 | 否 | 否 |
| 记录 | 是 | 否 | 是（作废态） |
| 数据集 | 是 | 否 | 否 |
| 批签发模板 | 是 | 否 | 否 |
| 流程模型 | 是（发布） | 否 | 历史 |
| 公式 | 否（仅确认） | 否 | 否 |

> 注：编号规则也有"编辑/确认/启用/停用"生命周期，但简化版本，可视为本机制子集。

## 通用状态机

完整变体（工艺 / 操作规程，含审批 + 生效日期）：

```
新增 → 编辑(草稿) ──确认──► 确认 ──发起启用审批──► 审批 ──通过──► 待生效/生效 ──停用──► 失效
                              ▲                      │                            │
                              │                  审核不通过                        │
                              └──────────────────────┘                            │
                              重新编辑                                  ──启用──► 回到「审批」
```

简化变体（配方 / 生产 BOM / 记录 / 数据集 / 批签发模板，**无生效日期**）：

```
编辑 ──发起审批──► 审批 ──通过──► 确认 ──启用──► 启用 ──停用──► 停用
                       │
                  审核不通过 → 回到「编辑」
```

记录特例：确认态可作"作废"，作废后仍可复制升版；记录无"启用"概念，确认即可被工艺引用。

## 多版本规则（关键）

1. **多版本共存**：同一对象可同时存在多个非「确认/生效」状态的版本（多个编辑、多个审批可并行）。不校验"编辑"状态版本唯一性。
2. **生效唯一性**：同一对象**全局最多一个**「生效/启用」版本。若已存在「待生效」或「审批(启用)」版本，禁止再次发起启用审批，提示已存在待生效或启用审批的版本。
3. **升版继承**：
   - 工艺升版：记录及组件的业务配置继承（包括组件功能配置、执行条件、完成条件等）。
   - 配方升版：配方物料信息继承。
   - 记录升版：组件实例及公式配置继承。
   - 操作规程升版：文件信息及分类继承。
   - 公式升版：公式表达式及参数关联继承。
4. **复制 vs 升版**：升版保持对象身份（产品/工艺名称不可改）；复制创建新对象（名称可改）。

## 生效控制

- **立即生效**：审批通过后版本直接转为「生效」，原生效版本自动转「失效」。
- **生效日期**：审批通过后转为「待生效」；定时任务到生效日期时切换为「生效」，原生效版本转「失效」。
  - 若生效日期 ≤ 审批通过当天，立即生效（同上路径）。
  - **立即生效按钮**：「待生效」状态下可手动触发立即生效，生效日期改为当天。
- **直接生效**（操作规程特例）：编辑/确认状态的操作规程版本提供「直接生效」按钮，跳过审批直接生效，原生效版本转失效；历史记录一条"直接生效"，操作日志记录"版本直接生效"。

## 双列表交互范式

配置端对象（工艺/配方/记录/操作规程）普遍采用双列表布局：
- **上列表**：对象列表（按对象创建时间逆序）
- **下列表**：选中对象的版本列表（按版本创建时间逆序）

按钮按版本状态动态展示：

| 版本状态 | 可执行操作 |
|---|---|
| 编辑 | 编辑、查看、确认（+历史） |
| 确认 | 启用、查看、历史（+重新编辑） |
| 审批 | 查看、审批进度、历史 |
| 待生效 | 查看、停用、立即生效、历史 |
| 生效 | 查看、停用、历史 |
| 失效 | 查看、启用、历史 |

详见 [[common-interaction-spec]]。

## 与两端模型的关系

[[product-overview]] 定义"配置端 vs 使用端"两端模型：
- **配置端**：本机制管瞎的对象（工艺/配方/记录/操作规程/数据集/批签发模板等）在配置端走完整生命周期。
- **使用端**：指令单/称量工单/批签发记录/物料件等**只引用已发布版本**，不进入版本机。

实例编号规则：
- 配置对象（记录/工艺/BOM/操作规程）：实例编号 = **版本号**（见 [[numbering-rule]]）。
- 执行对象（指令单/批记录/批签发）：实例编号 = **生产批号**。

## 合规约束

- 任何状态变更（新增/编辑/确认/发起审批/审批通过/退回/不通过/启用/停用/立即生效）均记录审计追踪，对象 = 「名称；版本号」。
- 启用审批需接入统一审批流引擎，详见 [[approval-flow]]。
- 配置对象的电子签名与历史记录详见 [[audit-trail-and-logs]]、[[esignature]]。
