# 菜单树与编码规则

> 本页是产品功能的**目录骨架**。每个功能的菜单编码是 product-wiki 页面 `menu_code` 字段的来源。
> 与 [[product-overview]] 配合使用。

## 5 级编码规则

编码共 5 级，每级 3 位：

```
100 100 100 100 100
└系统┘└父菜单┘└子菜单┘└权限分类┘└权限┘
```

| 级别 | 含义 | 示例 |
|---|---|---|
| 系统编号 | 标识子系统（见 [[product-overview]] 系统表） | `120`=MES |
| 父级菜单编号 | 标识父菜单（业务域） | `030`=生产管理 |
| 子级菜单编号 | 标识具体功能 | `001`=生产计划 |
| 权限分类编号 | 标识权限分类 | — |
| 权限编号 | 标识具体权限（按钮级） | — |

- 菜单国际化：前端以菜单编号为 key 加载 i18n 配置
- 图标关联：直接用菜单编号

## ⚠️ PRD 文件名编号的歧义性

`packages/prd/` 下文件命名为 `NNN-功能名.md`，其中 `NNN` **多数是「子级菜单编号」**，不带系统/父菜单前缀。因此：

- **同编号跨父菜单重复**：`001-库存管理.md`、`001-生产管理.md`、`001-货品信息.md` 分属不同父菜单的 001。
- **不能单靠文件名编号定位**，必须结合功能名与内容。
- 这正是 product-wiki 存在的意义：把散落、歧义的 PRD 按业务域重新组织并互链。

部分 PRD 文件以「系统编号」命名系统级总览，但多为空（见 [[SCHEMA]] 空 PRD 清单）：`120-制造执行系统.md`、`150-仓储管理系统.md`、`100-平台管理.md` 等 21 个为 0 字节。

## 权限模型（按钮级）

每个功能在 `菜单功能.md` 中以表格登记「按钮 | 操作类型 | 业务操作 | 对象 | 备注」，作为：
- **功能权限**：默认权限（不含删除/危险按钮）vs 管理权限（全部按钮）
- **审计追踪埋点**：每个按钮对应一条审计记录（见 [[audit-trail-and-logs]] 的按钮清单模式）
- **数据权限**：部分功能按部门授权（见 [[data-permission]]）
