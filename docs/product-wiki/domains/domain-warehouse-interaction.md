# 仓储交互业务域

> 跨 **WMS 网页端（150）** 与 **MES 网页端（120）/ MES APP（121）** 的协同域。
>
> 域核心是「**仓库 vs 车间**」边界：WMS 管仓库内的货品/货品件，MES 管车间内的物料件/暂存货位，通过"领料预定→仓库发料→领料接收"三动作衔接。

## 域职责

将仓库内的货品库存按生产批次的领料计划，**安全、可签名、可追溯**地交付到车间暂存货位，转化为物料件供生产消耗，并支持货品/物料的双向日志与盘点。

## 域内核心设计要点

1. **WMS 仓库内 vs MES 车间内 边界（核心）**

   | 责任 | WMS 仓库内 | MES 车间内 |
   |---|---|---|
   | 实体 | 货品 / 货品批次 / 货品件 | 物料 / 物料批次 / 物料件 |
   | 位置 | 货位（仓库区域） | 暂存货位（车间区域） |
   | 库存操作 | 货品入库/出库/移库/盘点 | 物料接收/入库/出库/移库/盘点/退库/销毁/使用/拆包 |
   | 业务衔接 | **仓库发料**（消耗货品件） | **领料接收**（生成物料件） |

2. **三动作衔接 WMS ↔ MES**（[[flow-material-flow]]）
   - **MES 领料计划预定**（批次量/物料量领料组件执行）：MES 校验 WMS 库存，向 WMS 发起预定；WMS 货品批次 `可用量↓ 预定量↑`。
   - **WMS 仓库发料**（网页端）：WMS 选货品件消耗发料，`预定量↓ 消耗量↑`；超出预定量部分扣减可用量。
   - **MES 领料接收**（移动端/批记录）：货品件 → 物料件转换，**继承批次信息**，原货品件号记入"物料来源"字段；接收完成后批量打印标签。
   - **取消发料**（WMS）：解除预定，`预定量↓ 可用量↑`，通知 MES。

3. **两类领料计划组件（[[record-dataset-master]]）**
   - 批次量领料（003）：按**货品批次**预定，强调按批次精确领料，组件字段含 物料批号/计划领料量/理论物料量/水分/含量/原厂批号 等。
   - 物料量领料（004）：按**货品（物料）**预定，不区分批次，组件字段含 物料名称/编码/规格/领料量/单位 等。
   - 物料预定（018）：仅预定暂存货位上的物料件，不发起仓库领料（用于配料混批场景）。
   - 三者都通过「组件配置 → 工序功能配置 → 批记录执行」三层落到批记录业务组件。

4. **量值恒等式贯穿所有操作**：`初始量 = 可用量 + 预定量 + 消耗量`，详见 [[material-master]] 量值模型。

5. **WMS 库存管理 vs MES 移动端库存管理 区别**：
   - WMS 库存管理（001）：网页端，操作对象是**货品/货品件/货位**，提供 货品入库/出库/移库/盘点；签名含 接收人+递交人 / 出库人+领用人 / 移库人 / 盘点人+复核人。
   - MES 移动端库存管理（004）：移动端，操作对象是**物料/物料件/暂存货位**，除常规操作外额外支持 物料退库/物料销毁/物料使用/拆包出库；扫码识别物料件标签与暂存货位标签。
   - 两者数据底座都是 [[material-master]] 的物料件/货品件 + [[location-master]] 的货位/暂存货位。
