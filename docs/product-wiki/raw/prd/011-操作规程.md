##### 数据权限
1. 新增文件时授权
    1. 新增文件，首次保存创建文件信息时，触发部门授权弹窗，必须选择部门信息才能点击确定；必须分配部门信息才能创建文件信息；确定保存时，工艺绑定所选的部门；
    2. 部门树展示当前操作人员所在部门、所属上级部门和下级部门信息；勾选部门节点，选中当前部门节点和上级部门节点，下级部门节点不会选中；
    3. 取消勾选部门节点，所选部门节点和下级部门节点取消勾选；
    4. 新增版本或编辑文件版本不会触发部门授权弹窗（已存在文件信息）；
    5. 一条文件数据可以属于多个部门信息；

##### 新增版本
1. 选择文件版本，点击【新增版本】按钮，跳转至新增版本页面，文件所有配置信息复制原版本，新增成功后，版本列表中增加对应的文件版本，文件版本状态为编辑状态；记录新增文件版本的审计追踪信息；
    1. 文件名称、文件编号、所属分类无法修改，为置灰状态；
    2. 未选择文件版本，点击【新增版本】按钮，提示请选择文件版本；
    3. 提交时校验“版本号”是否重复，若版本号已存在，则新增版本失败，给出提示：文件版本已存在；
    4. 文件可以存在多个编辑状态的版本，不校验“编辑”状态的版本唯一；

##### 编辑文件版本
1. 前置条件：文件版本为“编辑”状态，用户拥有“编辑”权限；
2. 选中“编辑”状态的文件版本点击【编辑】按钮，进入文件版本编辑页面，可以进行文件重新上传，文件版本保存时记录文件编辑的审计追踪信息；
    1. 文件名称、文件编号、所属分类无法修改，为置灰状态；
    2. 提交时校验“版本号”是否重复，若版本号已存在，则新增版本失败，给出提示：文件版本已存在；

##### 确认文件版本
1. 前置条件：文件版本为“编辑”状态，用户拥有“确认”权限；
2. 选中“编辑”状态的文件版本点击【确认】按钮，弹窗提示“确认后文件无法编辑，是否确认？”，确认后文件版本状态由“编辑”转为“确认”；记录文件版本确认的审计追踪信息；

##### 文件版本直接生效
1. <font style="color:rgb(49, 60, 82);">“编辑”和“确认”状态的操作规程版本，展示【直接生效】按钮，点击后弹窗提示是否让该操作规程版本直接生效，确认后该版本生效状态，原生效版本失效；</font>
2. <font style="color:rgb(49, 60, 82);">历史中记录一条“直接生效”的历史信息；</font>
3. <font style="color:rgb(49, 60, 82);">操作日志记录一条业务操作为“版本直接生效”的日志；</font>

##### 启用文件版本

1. 前置条件：文件版本为“确认”状态或“失效”状态，用户拥有“启用”权限；
2. 选中“确认”状态或“失效”状态的文件版本点击【启用】按钮，弹窗提示“是否发起启用审批？”，选择立即生效或生效日期，确认后发起启用审批成功；记录文件启用审批的审计追踪信息；
    1. 校验：未配置文件启用审批流程时，提示无启用的文件启用审批流程；
    2. 校验：若文件已存在“待生效”或“启用审批”的文件版本，无法发起启用审批，提示已存在待生效或启用审批的版本；
3. 发起启用审批后，文件版本状态由“确认”或“失效”状态转为“审批”；

##### 停用文件版本
1. 前置条件：文件版本为“待生效”或“生效”状态，用户拥有“停用”权限；
2. 选中“待生效”或“生效”状态的文件版本点击【停用】按钮，弹窗提示“是否停用该文件版本？”，确认后文件版本停用成功；记录文件停用的审计追踪信息；
3. 文件停用后，文件版本状态由“待生效”或“生效”转为“失效”；

##### 立即生效
1. 前置条件：文件版本为“待生效”状态，用户拥有“立即生效”权限；
2. 选中“待生效”状态的文件版本点击【立即生效】按钮，弹窗提示“是否立即生效当前文件版本？”，确认后该文件版本立即生效；记录文件立即生效的审计追踪信息；
3. 文件版本状态由“待生效”转为“生效”，生效日期改为当天，原“生效”状态的文件版本转为“失效”；

##### 查看文件
1. 前置条件：用户拥有“查看”的权限；
2. 选择文件版本点击查看按钮，进入文件版本查看页面；
    1. 查看页面无法进行数据保存，只能查看文件版本；

##### 查看审批进度
1. 前置条件：文件版本为“审批”状态；用户拥有“审批进度”的权限；
2. 选择“审批”状态的文件版本，点击【审批进度】按钮，进入审批进度查看页面；
3. <font style="color:#DF2A3F;">信息与配方审核-查看审核进度页面内容一致；</font>

##### 查看历史
1. 选择文件版本，点击【历史】按钮，弹窗显示文件版本的操作历史，以操作时间逆序进行展示；显示操作、操作时间、操作人、备注；操作类型：新增、编辑、确认、立即生效、启用审批、停用、审批通过、审批退回和审批不通过等；

    1. 点击【审核不通过】按钮，弹出审核不通过弹窗，输入审核意见和备注，确认后审核不通过；
    2. 审核意见和备注是否必填根据审核流程节点配置；
    3. 审核流程中节点配置“审核不通过”功能，当审核不通过时
        1. 若文件版本为启用审批，则文件版本状态由“审批”转为“确认”；
        2. 若文件版本为停用审批，则文件版本状态由“审批”转为“待生效”或“生效”（原状态）；
5. 审批流程通过
    1. 若文件版本发起启用审批时选择“立即生效”，文件版本状态由“审批”转为“生效”；原“生效”状态的文件版本转为“失效”；
    2. 若文件版本发起启用审批时选择“生效日期”，文件版本状态由“审批”转为“待生效”；
        1. 若生效日期是审批流程通过当天或之前的日期，则文件版本立即生效，同上；
        2. 新增文件版本生效的定时任务，到生效日期时，文件版本状态由“待生效”转为“生效”；原“生效”状态的文件版本转为“失效”；

##### 审批进度
1. 选择待审批的工艺版本点击【审批进度】按钮，进入查看审批进度页面；
2. 默认展示当前进行中的审核节点的节点处理信息，点击审核节点查看对应审核节点的处理信息；以处理时间逆序排序；

| **审批进度列表字段项** | **字段说明** | **固定（Y/N）** | **字段类型** | **字段备注** |
| --- | --- | --- | --- | --- |
| 节点名称 | 节点的名称，来源为流程配置中任务节点配置 | Y |  |  |
| 处理人 | 节点的处理人员，展示为用户名称-账号 | Y |  |  |
| 处理行为 | 节点的处理操作，来源为节点处理时动作 | Y | | |
| 处理时间 | 节点审核处理的时间，展示为“yyyy-MM-dd hh:mm:ss” | Y |  |  |
| 审核意见 | 审核意见，在审核处理时手动录入 | Y | | |
| 备注 | 备注信息，在审核处理时手动录入 | Y | | |
